# iOS parity baseline

This document records the current web implementation, not a delivered native client. Parity means preserving supported user outcomes while correcting implementation defects. Source inspection performed on 26 September 2026; device playback and account flows still need end-to-end validation.

## Proposed native acceptance criteria

1. **Browse and discover:** Choose a supported chart region, browse its top podcasts, search, open podcast details, paginate the full episode catalogue, search within a show and apply all six sort orders. Display explicit loading, empty and retry states.
2. **Library:** Follow/unfollow as a guest or account holder; retain guest subscriptions across launches; show subscribed podcasts and a deterministic newest-first release feed. Reconcile the two existing per-show release limits into one documented rule shared by clients.
3. **Accounts:** Sign in with an existing account, verify email codes, create an account, enroll/use a passkey and sign out. Use the existing identity and subscription backend. Verify native passkey association and session handling before treating authentication as complete.
4. **Transfer:** Import and export OPML through the system document/share interfaces. Merge imported subscriptions without losing existing data; report individual failures and retain failed device subscriptions for retry.
5. **Episode details:** Render readable show notes, open external links, seek from timestamps, share a canonical podcast/episode URL and support opening that URL into the corresponding native screen.
6. **Player:** Stream real enclosure URLs; preserve playback through navigation, screen lock and backgrounding; show a persistent compact player and an accessible full player. Support play/pause, seek, 10-second skip and the web speed choices. Preserve the chosen speed across episode changes and restore local playback state after relaunch.
7. **System integration:** Publish accurate Now Playing metadata and position, respond to headphone/lock-screen controls, handle audio interruptions and route changes, and expose AirPlay. Chromecast remains a parity item and requires separate device validation.
8. **Queue:** Append, inspect and play queued episodes; continue reliably at episode completion. Persist ordering and selection across launches. Adding removal and reordering is a proposed native improvement, not an existing web capability.
9. **Sync:** Save progress on meaningful lifecycle transitions and periodically during playback; restore the latest unfinished episode without automatically playing it. Retain unsent progress for retry. Establish and test conflict behavior between devices and account boundaries.
10. **Preferences and accessibility:** Support existing languages/regions and light/dark appearance with native controls. Verify VoiceOver labels/order, Dynamic Type, adequate touch targets, contrast and reduced-motion behavior. Support relevant external-keyboard playback/navigation commands on iPad.

These are release acceptance criteria, not evidence that their native implementation already exists. Downloads, sleep timers, chapters, transcripts, favourites, listening history UI, notifications and CarPlay are not implemented web parity requirements found in this audit.

## Gaps and discrepancies to resolve

- **Offline:** The README advertises offline PWA capabilities. Current source has a web manifest and IndexedDB subscription metadata, but no service worker registration, audio download manager or persistent queue/progress cache. Guaranteed offline listening would be new product scope.
- **Private feeds:** A feed URL can contain its own access token and is sent to the server for ingestion. The client should avoid logging or displaying the full URL, and the server still needs a documented retention/privacy policy for URL query credentials.
- **Search:** The README describes database search with an iTunes fallback; current text-search implementation calls iTunes directly. The web search hook does not pass the selected discovery region to the search API.
- **Guest/account separation:** Libraries are separate until a user explicitly imports device subscriptions. The current import-to-account UI clears all local subscriptions after a successful HTTP response, including feeds reported failed by the response. Native import must preserve failures.
- **OPML import:** The existing guest import replaces the local subscription map and only appears in the empty-library state. A failed feed fetch can abort the operation. Native import should merge and report partial results.
- **Queue:** The queue and current episode are not persisted locally or synced. Duplicate appends are allowed. There are no explicit remove/reorder controls. Finishing the last-index episode in a multi-item queue can leave an invalid selection; previous/next carries the prior seek position. Preserve the intended queue outcome, not these defects.
- **Playback restoration:** `restoreEpisode` records a paused episode without loading audio; the episode-detail Resume action can call an uninitialized audio player. Restoration must be verified with real playback, not only visible state.
- **Playback speed:** Keyboard speed actions pass an array index rather than the corresponding speed. New audio instances do not apply the stored speed. Both require native behavior tests.
- **Progress:** Completion is intended at 95%, but its effect observes duration rather than position. Episode changes do not explicitly flush the prior episode. The client restores only one most-recent unfinished item; there is no listening-history screen or per-episode resume lookup in the frontend.
- **Sharing:** The existing share component passes an empty URL and has no fallback for unsupported browsers. Native sharing should supply the canonical URL explicitly.
- **Media controls:** The Media Session position helper uses an incorrect API shape. AirPlay and Chromecast controls are visually hidden in the web compact mobile player. Native route and lock-screen behavior needs device tests.
- **Localization/accessibility:** Some strings remain hardcoded in English, and some icon-only controls lack accessible labels. Native parity should meet the intended accessibility and language coverage rather than reproduce those gaps.

## Validation boundary

This audit read the routes, UI components, client stores, playback integrations and relevant API/data functions. It did not mutate account data or exercise browser/device playback. Validate subscription changes, real audio, background interruptions, passkeys, AirPlay, Chromecast, cross-device progress and OPML round trips before signing off native parity.
